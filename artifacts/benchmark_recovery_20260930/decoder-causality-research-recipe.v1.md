**Decoder causality recipe — research only, not launched**

This recipe asks whether optional decoder display buffering explains part of the roughly two-second decode interval in the saved GPU prechecks. It tests the original packetized media at its actual one-AU-per-second cadence. It does not establish NVDEC busy time, model accuracy, policy benefit, publication readiness, or benchmark acceptance. No production source, corpus, specification, or frozen 5,600-arm matrix has changed.

The official [GStreamer nvh264dec reference](https://gstreamer.freedesktop.org/documentation/nvcodec/nvh264dec.html) exposes a writable max-display-delay property with default -1 since 1.24. That advertised default does not expose the internally chosen delay in the packaged decoder. NVIDIA's [Video Codec SDK reference](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/read-me/index.html) distinguishes output as soon as a frame is displayable from its separate immediate-decode sample path, whose supported streams contain only I/P pictures in the same display/decode order. Neither source establishes zero latency for this B-frame corpus.

Record loaded GStreamer version, decoder factory, plugin path/hash, linked-library versions, supported property range/flags and readback. Use the factory selected by the original GStreamer runtime. If it is not nvh264dec or does not support the reviewed property, report this control as unavailable; do not silently switch factories. Do not interfere with the guardian or another owner's containers. Run the later experiment sequentially during an agreed quiet interval with an exact reserved container identity.

2. Use the two original h264 files at the publication-v3 paths: front_gate and underbody. Hold and stream-hash their full actual bytes against the frozen media descriptors before/after the experiment; their old saved ffprobe metadata alone is not current byte custody. Select the first 32 AUs from each actual demux/parser sequence, with no search for a favorable prefix. Preselect AU sequence 9–24 for timing, sequence 1–8 for startup and 25–32 for lookahead/tail guard. Keep all 32 for output correctness. At source EOF, preserve and label EOS-only outputs rather than combining their flush timing with the central window.

Preserve and record actual negotiated caps/memory. It never constructs analytics models, queues for four analytic branches, the policy engine, guardian or publication acceptance. Persistent one-frame buffers or slow hashing can add backpressure, so record that limitation; this does not measure hardware decoder utilization.
