# Reassessment of the benchmark recovery

Authored after the four-arm experiment and the local runtime-bind diagnosis, before final CI and repository release closure. Earlier v1/v2 reviews remain historical snapshots.

The useful architectural boundary is now a real GStreamer baseline/shared pair for each analytics resource. CPU08 and GPU02 completed both arms at measured source B, with original zero exits, all-phase cold reconciliation, authenticated guardian cleanup, fixed input identities and released resources. An independent stock reduction reproduced the raw four-arm results. This establishes an operating component benchmark and a practical command the user can run again with a fresh output directory and still-valid inputs.

My earlier approach overcoupled that first useful result to broad backend qualification, remote capacity, accepted-policy authority and long publication campaigns. The separate component CLI removes those dependencies from this comparison while reusing the existing physical, native, model and domain checks. A private Linux ext4 root makes repeated physical validation practical. An owner/root/authority-bound session validates held inputs once within the pair's lifetime; public validators remain independent and live image/input checks remain required. The accepted runs support operability. They are not a controlled measurement of storage or validation speedup.

The boundary preserves the original scientific scope. Component results retain false qualification, accepted-policy, Q4 and full-publication eligibility. The original 32-arm, 1120-operation and 5600-operation campaigns remain unexecuted. Manual source review covers the named full-consumer guards, but direct negative regression coverage of every consumer is incomplete. Some consumers create work directories before rejecting the wrong authority kind. I cannot describe that as rejection with zero filesystem effects. These limitations stay visible in conformance.

I changed my interpretation of CPU07 after inspecting the original evidence. Its worker completed an inference response before frontend response delivery failed with EPIPE. The underlying socket-death cause is still unknown; a later Docker exit-zero event does not identify it. The scoped repairs preserve the first validated worker snapshot before teardown, distinguish invocation from delivery, and retain original native failure channels without replacing the primary error. Successful later CPU08/GPU02 runs support the operating route; they do not turn CPU07 into a success or prove why it failed.

The CI clock mismatch was a separate demonstrated defect. Real kernel audit time could fall outside the old fine-clock join because it came from the coarse clock. The repaired producer samples CLOCK_REALTIME_COARSE around the original syscall. The consumer requires versioned, same-owner, same-boot and correctly ordered evidence, retaining operation, journal and policy checks. Meaningful old-code failure and 51 focused tests support the change. Original hosted D then passed the full suite, all six native builds and all three required native regressions. Its selected-image fixture was corrected through three literal operands bound to the genuine existing receipt; every assertion stayed intact.

The local prerequisites exposed two more mistakes without requiring a benchmark redesign. Local C stopped before builds/tests when a verified HTTP response body timed out. The successor checkout exclusively copied eight already verified assets, and the unchanged stock size/SHA256/SHA384 verifier accepted their reuse. Original local D completed the tests but correctly failed the final skip audit: the real interpreter was installed, yet the checkout's required read-only bind was absent. The stock mount helper now materialized and checked that bind. The unchanged runtime test subsequently passed without a skip, and a fresh audit verified all 95 original benchmark input hashes and Linux identities. One full CI is now running with the corrected prerequisite in a fresh output. Earlier failed results remain failed.

I also omitted required arguments on an initial wrapper invocation; it stopped at usage validation before launching CI. A later metadata grant attempt used the wrong closure-file path and likewise stopped before grant or dispatch. I corrected those concrete errors without weakening the checks or altering the original outputs.

The scientific result is largely negative. Each arm admitted 1080 measured frames, with no censoring. CPU baseline/shared completed 516/664 and met 100 ms for 0/0. GPU completed 1070/1075 and met it for 3/1. Completed-frame medians were 5727.5/3621 ms on CPU and 2127/2168 ms on GPU. These different completed subsets prevent reading a median difference as a matched-frame causal speedup. Drops remain in the ingress denominator and receive no invented latency.

Six logical streams replay two recordings; NVDEC operates in both analytics-resource modes. Numerical model parity supports the declared topology/load proxy, not application accuracy. One baseline-first pair per resource does not separate order, thermal or shared-resource effects or establish population confidence intervals. Partial C_obs is attributed stage elapsed time with overlap, not processor work, energy or decoder busy time. Its lower shared total establishes no work or energy saving. The workload and 100 ms target stayed fixed. The benchmark now exposes those failures honestly.

The remaining architectural concern is the size of the control and evidence layer. It should preserve one original run and diagnose the first failure behind a usable public command. Additional wrappers or receipts are justified only by a concrete uncertainty. The current experiment does not justify another speculative native rewrite. Performance investigation should now use controlled, separately specified experiments while keeping the operating command stable.

At this snapshot, local full CI, independent current conformance, same-change sync/archive, latest archived-commit checks and exact final review remain pending. This document grants no future success. Final repository process evidence belongs to the same PR2, avoiding an endless series of commits that each require another final check.
