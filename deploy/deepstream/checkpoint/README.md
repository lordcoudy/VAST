# DeepStream checkpoint runtime boundary

This directory contains the DeepStream 7.0 capability probe, the dedicated
offline runtime image recipe, and the native metadata C ABI used by the direct
SDK runtime. It is intentionally separate from deploy/native_gst_probe: the
generic probe is not a checkpoint topology runtime and must not be relabelled
as one.

The execution boundary is implemented by the native SDK runner, the
fail-closed protocol adapter, and the protocol bridge under scripts/. The
runner constructs either 24 isolated baseline graphs or six shared-prefix
graphs with four bounded branch queues. The bridge fail-closes unless all of
these bindings are present:

- one direct-admission JSON v1 compressed access unit;
- an exact admission/AU identity copied into observed `NvDsFrameMeta`, with
  `nvv4l2decoder`, GPU 0, source/frame number and buffer PTS all matching;
- the topology-specific causal shape: one source/decode/preprocess chain per
  baseline branch process, or one shared prefix plus four bounded-queue fanout
  routes in a shared graph;
- an acknowledged native policy decision and path entry;
- a capability-bound analytics execution endpoint: OpenVINO on CPU or
  TensorRT through `enqueueV3` on `NVIDIA_CUDA`;
- matching input/output byte digests, analytics provenance and native resource
  fields, followed by an acknowledged policy terminal;
- direct-runtime v2 stage events and a protocol-v3 branch terminal. Synthetic
  fixtures remain `runtime_contract_test`; they are never native evidence.

The executable plan is generated by:

```bash
python scripts/checkpoint_deepstream_runtime.py plan \
  --scenario checkpoint_video_dag_shared \
  --codec h264 --policy heft --deadline-ms 100
```

The SDK/NVDEC probe runs one decoded buffer for each frozen codec:

```bash
python scripts/checkpoint_deepstream_runtime.py probe
```

Its JSON is engineering evidence only. Even a successful probe keeps
`publication_ready=false`.

The source, graph, adapter, and offline image recipe are implemented as
engineering artifacts. They are not an accepted benchmark runtime; therefore
topology_runtime_implemented=false and publication_ready=false remain
mandatory:

- Materialize and accept the DeepStream adapter configuration and native
  policy capability manifest for all eight CPU/GPU branch endpoints.
- Emit and accept one uniform native capability receipt per branch with exact
  implementation/emitter digests, decision/path/terminal acknowledgements,
  and service/transfer samples. The current bridge validates those ingredients
  but deliberately does not publish such a receipt.
- Provide semantically equivalent, frozen model implementations for CPU and
  NVIDIA CUDA/TensorRT analytics workers. The bridge enforces source-model and
  preprocess/output-contract identity, but no frozen DeepStream TensorRT engine
  set has been accepted; sample models cannot replace it.
- Bind accepted resource-v2 evidence, including external NVML decoder busy
  sampling and native fanout work. Analytics response resource fields alone do
  not satisfy resource-v2 publication evidence.
- Pass separate 24-process baseline and six-process shared hardware pilots with
  identical persisted admission schedule fingerprints. No KPP pair is present;
  one-buffer synthetic I420 H.264 and H.265 SDK/NVDEC pilots pass on the current
  Windows/WSL/Docker GPU path. An earlier non-I420 H.264 profile failed with
  CUDA error 801; none of these synthetic pilots is KPP acceptance evidence.
