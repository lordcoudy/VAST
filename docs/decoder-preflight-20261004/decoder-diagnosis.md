## Отказы сохранены по отдельности

**Исходный S2 research.** Front-gate/default завершил 32 AU. Front-gate/zero сохранил 32 packet/output/timing observations и source rc0, но проверка пакета завершилась `physical hash deadline exceeded`. Guest завершил один run; controller — ноль. Обе underbody серии не запускались. Эти поля и исходный отказ не переписаны после исправления.

Причина была в cached Pin: `libgstapp.so` получил deadline 48,930 с от guest start в первом run, завершившемся на 39,266 с. Cleanup второго run наступил около 74,178 с, но Pin проверял прежний уже истёкший clock. Наблюдавшиеся около 0,242 с от drain до terminal не доказывают исчерпания 15 с cleanup или слишком большого объёма hashing. P3/S3 назначает cached Pin текущий существующий абсолютный phase deadline перед неизменным rehash. Два controlled-clock теста на реальных файлах показали old RED/new GREEN для обеих направлений ошибки. Размеры, SHA, FD, named/ancestor identities, семь epoch fields и surrounding final-close guards сохранены; бюджет не увеличен.

**Исходный S3 cold.** Reader остановился с `Refusal: namespace count`. Фактические metadata36 превышали прежний предел32; controller103 и run14 укладывались в свои пределы. Второй отказ не был достигнут тем original cold. P4/S4 исправляет только представление reader: metadata40 = 8 fixed + 2×16 existing collections, mapping-only2MiB в BEFORE/CLOSED и source-READY чтениях тех же документов. General JSON/channel1MiB и metadata16MiB сохранены; orphan/alternate BEFORE names отвергаются. Original namespace-failed report остаётся failed.

**S4 CI.** Реальный concurrent-export тест выявил bootstrap до `.bundle.lock`: создание lock-file другим exporter меняло parent directory во время строгой проверки intent. Уникальная строка отказа доказывает короткий результат syscall, но original offset/requested/returned и positive-versus-zero не записаны.
