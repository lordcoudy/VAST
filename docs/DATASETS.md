# Benchmark datasets

`smoke_testsrc` is generated by `scripts/prepare_assets.sh`. It is intended only
for installation checks and smoke runs.

The optional public-dataset matrix uses `mot17_uadetrac_public`; it is not the
primary preregistered KPP architecture cell. Download MOT17 and UA-DETRAC from
their official distribution points and place the extracted raw sources under
`data/videos/`:

- MOT17: <https://motchallenge.net/data/MOT17/>
- UA-DETRAC: <https://detrac-db.rit.albany.edu/>

The public benchmark manifest expects six normalized clips under
`data/benchmark/`. Prepare or verify them with:

```bash
.venv/bin/python scripts/prepare_benchmark_dataset.py --dataset mot17_uadetrac_public
.venv/bin/python scripts/check_dataset.py --dataset mot17_uadetrac_public --mode benchmark
```

The preparation script maps the manifest clips to these local raw sources:

- `MOT17/train/MOT17-02-FRCNN/img1` -> `data/benchmark/mot17_02.mp4`
- `MOT17/train/MOT17-04-FRCNN/img1` -> `data/benchmark/mot17_04.mp4`
- `MOT17/train/MOT17-09-FRCNN/img1` -> `data/benchmark/mot17_09.mp4`
- `DETRAC-Images/MVI_20011` -> `data/benchmark/uadetrac_mvi_20011.mp4`
- `DETRAC-Images/MVI_40152` -> `data/benchmark/uadetrac_mvi_40152.mp4`
- `DETRAC-Images/MVI_40714` -> `data/benchmark/uadetrac_mvi_40714.mp4`

Each generated clip is normalized to 1920x1080 at 30 FPS with H.264. Existing
clips whose SHA-256 matches `configs/datasets.yaml` are skipped. Missing or
mismatched clips are regenerated atomically and rejected if the resulting
checksum does not match the manifest. The script does not edit
`configs/datasets.yaml`; update the manifest intentionally if source material or
encoding settings change.

## Local KPP recordings

`kpp_real_avi`, `kpp_real_h264`, and `kpp_real_h265` are based on two local
recordings, not six independent cameras. Their six manifest entries are logical
load replicas:

- five entries reference `source_id=kpp_plate_avi`;
- one entry references `source_id=kpp_underbody_avi`.

The H.264 and H.265 variants are CFR-600 transcodes used for codec and pipeline
load experiments. The front-gate source is 1920x1080; the underbody source is
1700x236. `camera_role` currently labels replica intent, but no accepted mapping
at dataset level states whether every logical stream enters all four analytics
branches or whether branches are selected per source/replica. Therefore the
manifests retain `analytics_routing: unresolved`; the primary checkpoint
scenario separately selects the declared non-production
`architecture_reuse_all_branches_v1` profile. Benchmark mode remains blocked on
physical topology and accepted native evidence, not on silently reinterpreting
`camera_role`.

These files can support a topology/performance experiment after routing is
fixed, but they do not provide six-camera scene diversity or accuracy ground
truth. `Timestamps.txt` is realism/event metadata for the underbody capture and
is explicitly not detection-accuracy ground truth.

When the two checksum-matching AVI sources and `Timestamps.txt` are available,
prepare either codec dataset with:

```bash
python scripts/prepare_benchmark_dataset.py --dataset kpp_real_h264
python scripts/prepare_benchmark_dataset.py --dataset kpp_real_h265
```

For a KPP `real_codec_transcode` dataset, the tool reads the source dataset and
transcode settings from the manifest. It deduplicates the six logical entries
into exactly two physical targets, verifies the source AVI SHA-256 before
encoding, uses the declared ffmpeg filter/encoder/preset/CRF/pixel format, and
atomically installs a target only when its SHA-256 equals the frozen manifest.
An already matching target is retained without requiring regeneration. After
all targets are present, `load_dataset` rechecks every logical stream, video
metadata through ffprobe, annotation bytes, ordered aggregate identity, and the
full logical manifest identity. The tool never edits `configs/datasets.yaml`.
`--dry-run` performs source/checksum planning without writing a target.

## Dataset identity and preflight

`scripts/check_dataset.py` validates every local file against the expected
SHA-256 and prints two distinct identifiers. `aggregate_sha256` binds the
ordered stream-byte checksums. The versioned `manifest_identity_sha256` binds
the complete logical dataset record, including stream order, source and camera
roles, codec and geometry metadata, expected media/annotation checksums, and
routing metadata; host-specific absolute paths and recomputed runtime fields are
excluded.

Every completed benchmark run stores both identifiers and the resolved manifest
record in `run_metadata.json`. The publication report reloads the configured
manifest and recomputes the identity fail-closed. A matching dataset name alone
does not establish provenance, and any intentional manifest change requires a
new pre-result contract rather than post-hoc editing of completed metadata.

Use `--dry-run` to inspect regeneration work without writing files, and `--force`
to regenerate clips even when checksums currently match.

## Strict validation runbook

After telemetry adapter changes, run the full local strict matrix with:

```bash
.venv/bin/python scripts/validate_strict_telemetry_fix.py --clear-runtime-artifacts --policies all
```

This command prepares and validates `mot17_uadetrac_public`, builds local native
probe prerequisites, rebuilds derived DeepStream/Savant probe images, clears only
`.cache/savant` and `runs/strict_validation`, then runs `canonical_heterogeneous`
for all strict local adapters across all configured scheduler policies.

The runner rejects benchmark mode while a checksum is missing, uses a placeholder,
does not match the local file, or while native schema-v2 telemetry is incomplete
or malformed.
