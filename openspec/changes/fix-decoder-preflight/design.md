## Risks / Trade-offs

- [Original filesystem mechanism is inferred] → Both-view records and one genuine guest deployment prove only the observed join; no overlay/kernel diagnosis or memory integrity claim is added.
- [ABI mismatch, VMA coalescing or unavailable proc view] → Fail closed with bounded original facts; no capability, fallback or repeated attempt. Verify host and guest ABI separately.
- [Cleanup failure hides a primary cause or skips another close] → Nested retirement, first-cause precedence, close/late companions, genuine FD/mmap faults and actual15s regression cases; unavailable close stays unknown/nonzero.
- [Tasks/archive bytes drift or historical inputs are rebased] → Four immutable raw P copies, supported repository/worktree interface, exact S runtime pins and separately frozen physical authority.
- [Nested tests are invisible or import another version] → One isolated discoverable adapter, exact module origins and individual66+new outcomes in actual hosted CI; ignored files must be tracked.
- [A prepared cold source is mistaken for accepted evidence] → Exact new observer source review/physical availability, independent mode-specific closed replay and actual once-only output records; both original readers remain immutable.
- [A failed conditional run is presented as completion] → Preserve prefix/nonzero/unknowns; keep research/central timing/full campaign counters truthful and require a further reviewed correction for any subsequent attempt or adoption.
