## 2026-09-25 qualification failure and native reset-check repair

The Sep24 pilot (InvocationID `d6a86cf4cee04a6a9bce3411f4f4a546`) exited 1 at 2026-09-25 00:51:56 UTC on cell 17 of 32, the first OpenVINO GVA CPU/H.264 independent-processes cell. The symbolized stack ended in `g_value_reset` inside `NativeProbeRuntime::verify_checkpoint_reset_state_before_ready`; a property-type replay observed GstAppSrc `current-level-buffers` as `guint64` while queue elements expose `guint`. The reset check read every such property into a `guint`, so the 64-bit write corrupted the adjacent iterator `GValue`. The guardian (InvocationID `d784dc0a11574cd385cc0c20d27e0cc0`) was stopped through its authenticated control path: `clean_stop_nonpublication`, zero failed requests/connections, `publication_ready=false`.

The repair adds `read_current_level_buffers`, which reads through a `GValue` of the declared type (`G_TYPE_UINT` or `G_TYPE_UINT64`) and throws on unreadable or other types, and extracts the reset-path loop as `verify_pipeline_queues_empty` with cleanup on every exit. The new `tests/cpp/checkpoint_native_reset_queue_level_test.cpp` runs in the discovered native runner. It uses a real `appsrc ! queue ! fakesink` pipeline (asserting the two widths), a 2^32 guint64 level that a 32-bit read would truncate to zero, mixed-width empty and nonempty queues, and unsupported/unreadable property types, with GLib warnings fatal. Against a scratch copy restoring the old `guint` read, it aborted with `*** stack smashing detected ***` (exit 134). With the repair, the 3-test native runner passed under WSL (GStreamer 1.24.2, frozen interpreter), as did the repository-integrity (3), checkpoint-runtime (43), scenario-planning (74), full-resource v2 (11), CUDA-transfer intervals (2), OpenVINO/GStreamer image source (4/6), publication-matrix (8), full-publication entrypoint (62), benchmark-contract (112, one skip) and resource-interval (19) suites.
